## Problem and scope

The packet's early live-head == admitted-head requirement blocks the existing trusted-opt-in FAB readmission positive. Readmission before material validation can spend delta models on an invalid train; readmission after train review advances beyond reviewed bytes. Fix this in `train_runner.py` and `train_review_packet.py` by freezing a non-authoritative prospective packet, using existing broker readmission, then promoting only matching durable identities. Preserve P3 publication/admission, P4 merged-outcome recovery, `_fab_delta_readmit`, `_commit_broker_readmitted_head`, actual broker routing/receipts, downstream verification, pinned merge and the FAB promotion re-gate. No second admission writer, duplicate authority validator, automatic retry or new native-readmission workflow.

Changed live head is eligible only in ordinary governed merge execution with durable FAB run ID, current promotion enabled, existing readiness interlock enabled and trusted shortcut opt-in enabled. Any ineligible stale pending node holds the entire invocation before sibling proposed preparation or effects. Merged nodes are never readmitted. Preview, review-only and native-request-only take only the already-admitted path. Native fills plus any proposed-head requirement return `native_fill_stale_request` before recovery, delta review, broker grant, train review or merge; fills are not silently refreshed.
2. **Freeze the entire prospective packet before effects.** Use a distinct internal prepared-snapshot type with explicit proposed-head mapping and separate prior durable bindings. Never fabricate ledger records or advance `completed_nodes`. Eligible changed nodes require manifest head, attested-command head, check-run head and disposal assertion head all equal to the proposed head; old-head evidence rejects. Other pending nodes require admitted-head evidence. Snapshot all Git, evidence, context, certificates, final node identities and train metadata. Retain prospective immutable admission binding (node, branch, PR URL, head and bound FAB run ID). Render and preflight the exact prospective artifact bytes for every node, including the last, before any revocation-store read, recovery, delta model or grant. Prepared values cannot enter packet storage, approval cache, native or reviewer sinks. Finalization may not reread evidence/Git content, rewrite identities, append text, change escaping or grow these bytes.
3. **Use existing recovery and durable readmission.** After the all-node material barrier, check actual durable revocation for every pending FAB-active node before the first recovery. Immediately before **each** recovery call, independently recheck its current flags, real revocation store, durable prior binding and live identity; an earlier all-node check does not cover later-node races. Then recover to that current durable admitted prefix. Unchanged-head torn recovery still runs when promotion is on and shortcut is off; preview/review-only/request-only never run recovery. Only eligible changed nodes call existing `_fab_delta_readmit` pinned to the prepared prior/proposed pair. Preserve its provenance/fsync/gate/transaction/scope/author/broker/receipt/post-grant-revocation checks. None, refusal, exception or identity mismatch holds before train review/merge. Current flags are checked again before entering the helper; no stale opt-in authorizes new readmission.
4. **Finalize from fresh durable authority and frozen bytes.** Re-read ledger after successful readmissions. Every pending record must match its complete prepared prospective admission binding; helper return alone is never authority. Re-read live PR state/head/base, verify historical merged identities/outcomes, and check fresh actual revocation before train/cache/native sinks. Finalization promotes only the already rendered snapshot; assert identical artifact bytes/hash. Store/read back immutably. Refresh `completed_nodes` from this durable state, not helper return or P3 live-preferring values. Validate supplied native binding before cache reuse. `emit_native_request` emits the exact finalized packet and returns independently of cache eligibility: a cache hit cannot reach merge. Emission requires every pending node already match durable admission; it never performs recovery/readmission. Otherwise digest/current-floor cache or the existing bounded train review may authorize progression.
5. **Fresh checks before approval and every pending merge.** Immediately before appending approval, re-read durable ledger and compare immutable admission binding with the packet, recheck live PR head/base and fresh actual revocation. Repeat before every pending merge, preserving downstream merged-SHA re-verification, `--match-head-commit` and current FAB promotion re-gate. Do not pass an earlier packet-state snapshot as current durable truth. Benign status transitions to merged require historical outcome validation rather than being treated as head drift. Remove late readmission and torn recovery from the merge loop; keep its fresh read-only revocation. Any observed head/base/admission change holds remaining nodes without another delta review, packet rebuild, native emission or train round. Already merged upstreams remain recorded.

## Actual read-only revocation source and flag semantics

At every required revocation gate, for each pending node with a durable FAB run ID and current promotion enabled, freshly resolve `repository_broker_namespace(workspace)` and read a real `BrokerEvidenceStore` at that namespace. Namespace derivation is pure. Require the namespace directory to exist; resolution, construction, unreadable or malformed-store failures produce a typed hold. Never substitute None or an injected always-clear object after an error. The read path must create no namespace/store files or call broker authorization/append. With the current active FABPUB capability the constructor does not create directories; require existing namespace before construction in all supported cases. Existing namespace with no `evidence.jsonl` retains the store's established empty-replay semantics; absent namespace and unreadable evidence are different conditions and must not be treated as clear.

`epoch_blocked` calls `replay()` on every access and also checks authenticated legacy partition ambiguity, so use it at each gate rather than caching an earlier boolean. Retain the helper's own authoritative post-grant check. Tests write revocation into the actual durable evidence store under the actual repository namespace, including revoke of node 2 after the initial barrier but before its recovery. Node 2's recovery must not run or mutate its FAB state; earlier durable admission stays; no train approval/review/merge follows detected revocation.

Review-only and native-request-only still perform the promised pre-sink/approval read-only revocation checks for FAB-active pending nodes, using an existing namespace without creates. They never repair provenance, admit a head or merge. CLI preview remains before broker construction/lease/ledger effects and never consults broker evidence. Promotion-off skips FAB revocation/recovery/readmission/re-gating under existing current-flag policy; ordinary packet/admission/head-pin checks remain. Switching promotion off after a completed broker readmission does not retroactively revoke that grant: full train review still covers the admitted delta and merge retains its head pin, while the FAB gate follows its existing flag-off behavior. No new native-readmission workflow or extra round is introduced.

## Approval mapping, identity and failure durability

Train approval is one synthetic `_TRAIN_REVIEW_NODE_ID` record, separate from all real node IDs. `read_ledger` folds last record per node ID, so this append does not replace a node's head/PR/FAB fields. Preserve that design: global approval carries reviewer-floor/policy and packet digest, not one arbitrarily selected node's admission. Tests inspect the actual ledger mapping before/after approval and verify every real node's durable admission binding survives, including the real routing positive's delta head/FAB run ID. Fresh comparisons bind immutable identity, not an incidental pending/merged status label.

On caught recovery/readmission failure preserve `merge_halted` / `fab_readmit_failed`, but freshly read the latest durable node record before blocked evidence. Preserve that record's head, branch, PR URL, FAB run ID, merge order and other admission fields; never replace it with stale caller fields or a branch-only row. A failure before durable append preserves old binding; an exception after append/before return preserves the successfully readmitted new binding. Missing/unreadable identity holds without inventing a grant.

P3 already treats `blocked` + branch + PR URL + head as an admission-preserving refused-refresh binding and carries its FAB run ID. Packet preparation must accept that same complete binding with all ordinary live/head/material checks; incomplete blocked records remain unadmitted. Test complete and incomplete records, crash and caught-exception resume. Admission does not arise from a prepared packet, helper return or broker head alone.

Crash before grant leaves old ledger authority and existing torn-recovery obligations. Crash after grant but before ledger append can replay the exact v2 authority digest under existing broker dedup; different authority, revoked epoch or subsequently advanced branch refuses. The retained real routing probe shows epoch 2/store count 2 reused while the helper calls its injected delta reviewer again on explicit retry. This is not zero-model recovery. Add no automatic retry; an exhausted review allowance remains a hold unless a further round is independently authorized. Crash after durable append resumes from that new binding and does not repeat successful readmission simply because packet/approval is absent.

Invalid material, stale evidence, unavailable objects, unsupported content, bad history or prompt overflow anywhere in preparation causes zero recovery/delta/grant/train-model/approval/native/merge effects. Later-node readmission failure retains earlier durable admission but triggers no train model or merge; no whole-train rollback or invented atomicity. Historical merged sections retain their original source identities and actual outcomes; a partial legacy train without bound history remains held. Helper transaction/scope failures can still occur after its existing authorized delta review; no claim that all helper failures precede models. Duplicating that authority checker is deferred.
