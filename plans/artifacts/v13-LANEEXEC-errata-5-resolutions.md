## Journal, ownership and lifetime (5b, 6b, 9b)

SL-3a precursor (existing owners of `sandbox_placement.py`, `launch_service.py` and `tests/test_launch_release_reap.py`) must **produce** the following private lifecycle methods in `sandbox_placement.py` (clock deadlines below are absolute monotonic seconds unless named timeout_s):

- `launch_request_lock(request_id: str, *, timeout_s: float) -> ContextManager[bool]` serializes short record transactions per client/request. `launch_lease_lock(reservation_id: str, *, timeout_s: float) -> ContextManager[bool]` is a distinct per-client/reservation exclusive OS lock. A true context value means acquired. Use stable private lock files. Keep leases separate from rung leases.
- `ReservationLock.ensure_prepare(request: LaunchRequest) -> PreparedPaths | str` shares the landed prepare allocator under an already-held lock, including root/window/echo checks, durable assignment and reuse. Return the launch refusal code on mismatch. Only non-Pi requests may allocate here. A Pi request must have the exact paths. No synthetic public prepare ID or nested lock. This is an early caller transaction; the supervisor takes its journal lock later.
- `fence_launch(reservation_id: str, request_id: str, *, cause: str, deadline: float) -> bool` durably fences only the matching ownership generation, records the cleanup debt, inhibits start and publication of return bytes, and makes the launch window closed and flags fenced. `renew_launch(reservation_id: str, request_id: str, *, deadline: float) -> bool` confirms only timely slot **and** journal completion for that unfenced generation. Use a bounded, supervised I/O operation with a generation-specific journal record. Drain or quarantine outstanding writers before reusing a slot. A late write cannot clear a fence, move h or revive an owner. Treat a successful lease confirmation at claim as h, read T from the stored reserve binding, and follow the wire T/3, 2T/3 and h+T boundaries. An I/O timeout leaves debt even if its helper subsequently completes.
- `cancel_launch_owner(reservation_id: str, request_id: str, *, deadline: float) -> str` addresses the verified supervisor before WORKER registration using a private per-generation control socket, peer uid and retained pid/start identity; after registration also use the landed verified WORKER cancel. Return the existing CancelOutcome vocabulary. A pending or zero-signal result keeps the claim. Wire `LaunchService.cancel` and release/reap to this operation in `launch_service.py` and the lifecycle. Never signal a recycled PID or journal PGID.

**Record protocol.** Before admission serialize by client/request ID, hash the complete canonical launch body, compare any existing digest, return a matching stored terminal verbatim, and reject a different body without touching the record. Elect one caller by exclusively creating an in-flight record with verified process/start identity and a fresh generation. Release the record lock before expensive work. A same-body duplicate attaches and waits in bounded observations, checking cancellation and the durable terminal, never spawning another helper or taking ownership from a live original. Bound recovery checks by ANSWER_BOUND_S per call. A verifiably dead pre-claim owner with confirmed no claim and no handoff settles a generic pre-claim refusal. When liveness cannot be established, an ambiguous handoff or missing terminal after claim reports wire-valid uncertain on bounded observation, preserves the generation and claim, and leaves reconciliation to reap. A transient uncertain observation is never stored over the original terminal. Use one compare-and-set under the short request lock for every record transition, including terminal; bind it to the owner and generation. Hand off once to an identified supervisor which acknowledges ownership durably before caller ownership ends. Crossing caller exit after that acknowledgement leaves the attempt running.

**Allocation and claim.** Each elected request journals a private stage beneath trusted client storage, outside any prepare run a concurrent release can remove. Record reservation, request, run, generation, owner and exclusive stage name before creation. Only matched dead-owner stages are collectible. Different IDs may stage concurrently. The supervisor takes the lease and then the reservation journal lock, rechecks window, prepare, expiry and claim, and checks its own start identity before provisioning. A held winning claim refuses a contender as exec_claimed even while the winner holds the lease (read claim under a short bounded transaction if the lease is busy). Record intent for a generation-named scratch allocation before exclusive creation. Provision there, record its device/inode, fsync and rename without replacement to the prepared path under the same lock; recover from either side of rename by matching identity and intent. Unknown or foreign ownership leaves debt. Call lock.return_dir(run_id) under that lock to provision the retained parent in returns/ outside runs/. Pass its result to collection. Finish with lock.claim(request_id, run_id, owner=verified_identity) and release the journal lock immediately. Missing identity returns capability_unmet with zero starts and no rollback record. The supervisor holds the lease through durable terminal publication. Failure paths remove only their own staged allocations. A pre-claim crash leaves a recoverable intent, never authority to clear a claim.

**Post-claim interlock.** Serialize start authorization, return publication, generation fence and cancel with a distinct per-generation operation lock. The supervisor validates the unfenced generation and durably marks start-intent before entering the bounded spawn under that lock. An uncertain start keeps the claim. Release/reap obtain the journal lock only to snapshot ownership and mark release intent, then drop it before requesting the operation fence, signalling, waiting for terminal, or acquiring the lease. No path waits for the lease or operation lock while holding the journal lock. Only after acquiring the lease and rechecking generation, terminal (or a verified dead-owner disposition) and cleanup evidence under the journal lock may teardown proceed. A timeout at any stage yields cleanup_pending. Treat unbounded spawn or blocked I/O as unresolved debt with activation gated on bounded containment. Terminal metadata remains publishable while fenced. A durable fence blocks any later chain start or retained byte publication.

For a closed rollback cause the live supervisor retains the lease, obtains a fresh journal lock for at most the remaining release allowance, and calls lock.rollback(request_id) only with proven zero starts, matching claim and the closed-cause evidence. Persist cause/intent before CAS and finish the request terminal before releasing the lease. A rollback marker proves a completed CAS across crash recovery; an intent alone never does. A timeout, unknown remote effect or unconfirmed CAS keeps the claim uncertain. Reap scans fenced/debt records and claims with verified gone owners even before expiry. Record fencing and debt before teardown, and keep the allocation until descendant exit and parent collection (remote expiry/barrier on OpenShell) are independently confirmed. Never manufacture acknowledgement, a completed cancellation, or rollback on restart. Retained returns survive ordinary release/reap until tombstone expiry.
