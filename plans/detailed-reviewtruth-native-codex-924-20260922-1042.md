## Decisions

1. **Codex resolution with a non-disguising host guard; no Claude unification.** Snapshot one injectable environment (`base_env`/`env`, otherwise the process environment) and reuse the existing verified signature definitions, inspecting matches directly even when the child sentinel hides AUTOSEL candidates. Omitted inputs never disable ambient native detection. Add optional `host: HostContext | None` to the native builder, payload and fill-preflight APIs; pass context explicitly, never as fabricated environment markers. Thread the same snapshot/context through CLI and governed entry guards, Codex emit, builder, preflight, apply and both invoker paths. Do not reinterpret AUTOSEL's `executor=None` as proof of standalone execution. Compute this pure routing decision before effects; report refusals in decision 5's exact monitoring order:

   | Evidence | Native-routing decision |
   | --- | --- |
   | Verified Claude signature and retained `_under_claude_code` disagree on the same snapshot | Ambiguous: refuse the whole board/request before effects, including whitespace-only legacy markers; do not clear or normalize markers to choose a route. |
   | Child sentinel plus any verified host signature, or both verified Codex and Claude signatures match | Ambiguous: refuse the whole board/request before effects, even if explicit context chooses one host. |
   | Exactly one verified signature, no sentinel, and explicit `HostContext(None)` or a different host | Context conflict: refuse the whole board/request; caller assertion cannot hide a marker. |
   | Codex signature only, no sentinel, and omitted or agreeing context | Confirm Codex routing. |
   | No verified signature, explicit `HostContext("codex")` | Accept the caller-supplied Codex routing context; sentinel-only does not contradict it, and context grants neither authentication nor execution authority. |
   | Claude signature only, no sentinel, omitted or agreeing context | Preserve existing marker-keyed Claude deferral and fill behavior. |
   | No verified signature, omitted context or `HostContext(None)` | Preserve existing standalone-routing semantics, including sentinel-only children; no Codex native request and no claim that missing markers prove physical standalone execution. |
   | No verified signature, explicit non-Codex context | Preserve existing host-leg/gateway checks and routing, including sentinel-only; notably explicit Claude context alone does not acquire native-fill eligibility. |

   Keep `_under_claude_code` unchanged. Its raw truth test differs from stripped verified signatures: `CLAUDE_CODE_ENTRYPOINT=" "` and `CLAUDECODE=" 1 "` are explicit disagreement controls, both alone and alongside Codex. The first three rows intentionally refuse some calls that previously deferred Claude; they never convert those calls into TUI launches. Sentinel alone stays child-compatible. Sentinel **plus Codex is routine**, however: `child_executor_env` preserves `CODEX_THREAD_ID` while stamping every executor child. Boards inside such children now refuse, including a Codex child's own shell; resolving that requires a future typed parent/child discriminator outside this plan. This does not qualify markerless hosts or repair Claude context-only semantics. Use existing `UNAVAILABLE`/CLI-refusal surfaces with routing-detail prefixes `native_host_ambiguous` and `native_host_context_conflict`; these are not new statuses or fill-refusal reasons. Pure request APIs raise `ValueError` with the same prefix; supplied-fill APIs retain their typed vocabulary. Never clear production/provider markers, infer a host from a model tier, or enable other native routes.

   `governed_board_gate` must apply the pure host guard before `prepare_review_composition_authorization`, `compose_fn`, auth/availability probes or scratch/request allocation. It owns one snapshot and forwards that snapshot/context to payload, preflight and invoke. The CLI does likewise before composition. Existing train adapters already enter this gate; they remain unchanged. Negative tests enter these actual production boundaries directly with forbidden-effect spies; the sanctioned helper pre-mints authority and therefore cannot prove zero-mint refusal.
2. **Defer an eligible Codex seat before dispatch; retain composition.** Eligibility requires `vendor_family == "codex"`, a resolved `codex` lane and subscription/homebrew backing on a confirmed Codex host. Resolve bare lanes with existing static model/lane metadata, without availability/auth effects, before the all-native predicate; it and mixed-board `_run_seat_body` must agree. Short-circuit before `render_seat_invocation`, `resolve_seat_env` and spawn, including injected spawn. Other host-vendor lane/auth/backing mismatches refuse before effects with `native_host_route_unsupported`, never through `opencode`, API or gateway. Under confirmed Codex, the verified and legacy Claude predicates are both false: positively prove Claude reaches its TUI/spawn seam and Gemini/Grok reach their spawn seams while Codex does not.

   Leave `compose_review_board` auth-aware and unchanged: its availability/auth CLI probes are metadata checks, not reviewer launches or native authority. A failed probe can remove OpenAI and backfill another vendor; report that composition shortfall as no Codex seat/no request, not a native deferral or satisfied host seat. Qualification starts with an already-composed eligible seat; host metadata never supplies auth. This plan does not solve native admission when CLI auth/availability is unavailable. Exercise the real composer with independently injected availability and auth outcomes through emit, not only a prebuilt board fixture.
3. **Extend the existing protocol, with explicit request-side posture.** The Codex request names a native Codex subagent, never a Claude affordance or an assumed host-specific tool name. Its emitted text and resolved instructions state: read only the staged review bundle; no execution, writes, network or tools beyond reading that bundle. This is a tested request statement, not enforcement proof. `native_agent_leg_request(leg="codex")` raises `ValueError` with `native_host_required:codex` unless routing confirms Codex; ambiguity/conflict retains its earlier refusal. This intentionally changes the public Codex builder's former host-free, Claude-worded output; inspected in-repo callers/tests use default or explicit Claude, whose builder remains compatible. External caller compatibility is not claimed.

   Keep a common **base acceptance brief**. One pure helper appends the fixed Codex-only posture to that raw resolved base exactly once; Claude is the identity transformation. The builder receives the raw resolved base, constructs effective native instructions, and the payload writes/hashes `request.instructions`. Governed/CLI emit write those payload instructions, then bind the read-back text and digest consistently. `brief_sha256` means expected effective **native** instructions for Codex: every production fill-preflight caller computes it with that same helper from the current resolved base and routing, never from untrusted emitted/fill contents. The invoker independently recomputes before binding. Keep broker authorization digests and other seats' staged instructions on the existing base brief; native posture is not a new restriction on other vendors' granted sandbox capabilities. Update the builder docstring's same-acceptance-brief promise to describe this explicit extension. No double append, transport rewrite or new authority input is permitted.

   Payload, loader and preflight share Codex eligibility. Accept `--native-leg codex=<dir-or-request.json>` on both commands; retain `claude=` and `claude.md` only for Claude, while Codex uses `review.md`. Derive continuation, the advisor-board shortfall hint and `filled_by` from the request's leg/seat. Alias must agree with emitted seat/model; never relabel current digests as emitted-request digests. Artifact, effective-native brief, composition, request and seat bindings, stale-train refusal, author exclusion, duplicate refusal, verdict-less degradation and bind-before-president remain load-bearing. CLI/governed fill preflight precedes isolation minting; invoker fill preflight remains after authorization checks and before dispatch. No new classifier or approval count is introduced.
4. **State the single-request boundary honestly.** This cell qualifies emit for exactly one eligible Codex seat. Refuse multiple eligible Codex seats before request files or reviewer effects. Auth-aware backfill can routinely create this case when another vendor is down. The library may return separate typed deferrals, but no unfilled seat counts and this plan adds no multi-request CLI. Keep Claude's existing `seats[0]` emit behavior unchanged and explicitly residual on agent-harness#924; do not apply the new count check to Claude.
5. **Heartbeat-only remains unsupported for native seats.** Compute the pure host decision from the same snapshot, but preserve refusal precedence: existing authorization/policy mismatch at the invoker; invalid policy; heartbeat timeout conflict; supplied fill with the exact existing `review_monitoring_unsupported_route:native_fill`; then host ambiguity/context conflict; then native-host-only refusal `review_monitoring_unsupported_route:native_host:<vendor>`. The latter applies to confirmed Codex or marker-keyed Claude host-vendor seats. Existing explicit `seat.host_leg`, transport/API and other route checks remain; no invalid route becomes admitted. Put the common pure ordering in the monitoring preflight and use it consistently at CLI/invoker boundaries; do not raise an eagerly computed host diagnostic ahead of a supplied fill. Governed review has no monitoring-policy parameter today: it gets the precomposition host guard, not a new policy surface or an automatic bounded fallback. Production gate execution remains closed under this plan.

   All policy/host refusals precede availability/auth, request directories, minting and launch. Intentional changes: Claude-marker heartbeat boards without fills now refuse whole-board; Codex-host boards do not launch their own CLI. Consequently the default heartbeat board invoked under Codex refuses every time. Retain the Claude-bounded control and marker-neutral default Gemini result.
