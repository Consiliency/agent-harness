## Decisions

1. **Codex resolution with a non-disguising host guard; no Claude unification.** Read one injectable environment (`base_env`/`env`, otherwise the process environment) and reuse the existing verified signature definitions, including all matches and the child sentinel. Do not reinterpret AUTOSEL's `executor=None` as proof of standalone execution. Thread this pure routing decision through Codex emit, builder, preflight, apply, both invoker paths and monitoring admission; do not re-detect against a different environment. Apply the following order before effects:

   | Evidence | Native-routing decision |
   | --- | --- |
   | Child sentinel plus any verified host signature, or both verified Codex and Claude signatures match | Ambiguous: refuse the whole board/request before effects, even if explicit context chooses one host. |
   | Exactly one verified signature, no sentinel, and explicit `HostContext(None)` or a different host | Context conflict: refuse the whole board/request; caller assertion cannot hide a marker. |
   | Codex signature only, no sentinel, and omitted or agreeing context | Confirm Codex routing. |
   | No verified signature, explicit `HostContext("codex")` | Accept the caller-supplied Codex routing context; sentinel-only does not contradict it, and context grants neither authentication nor execution authority. |
   | Claude signature only, no sentinel, omitted or agreeing context | Preserve existing marker-keyed Claude deferral and fill behavior. |
   | No verified signature, omitted context or `HostContext(None)` | Preserve existing standalone-routing semantics, including sentinel-only children; no Codex native request and no claim that missing markers prove physical standalone execution. |
   | No verified signature, explicit non-Codex context | Preserve existing host-leg/gateway checks and routing, including sentinel-only; notably explicit Claude context alone does not acquire native-fill eligibility. |

   Keep `_under_claude_code` and its marker semantics unchanged. The first two rows are intentional new pre-effect safety refusals, including ambiguous calls that previously deferred Claude; they never convert such a call into a TUI launch. The launcher stamps every child, so sentinel alone is not a new global refusal. This does not qualify markerless native hosts or repair Claude context-only semantics. Use existing `UNAVAILABLE`/CLI-refusal surfaces with stable routing-detail prefixes `native_host_ambiguous` and `native_host_context_conflict`; these are not native-fill refusal reasons or new statuses. Pure request APIs raise `ValueError` with the same prefix; supplied-fill APIs retain their existing typed refusal vocabulary. Do not clear markers, infer a host from a model tier, or enable other native routes.
2. **Defer an eligible Codex seat before dispatch; retain composition.** On a confirmed Codex host, subscription/homebrew OpenAI seats on the `codex` lane defer as empty-text `UNAVAILABLE/under_codex` with exact cognition, seat identity, artifact and resolved brief. The all-native early return and mixed-board `_run_seat_body` use the same predicate; short-circuit before `render_seat_invocation`, `resolve_seat_env` and spawn, including injected spawn. Add `under_codex` to `_TYPED_UNAVAILABLE_DETAILS`; apply accepts only the matching vendor's deferred detail. Preserve `enforce_native_host_leg`'s existing gateway exception and authorization/revalidation order. For other host-vendor lane/auth/backing mismatches, refuse the whole board before effects with `native_host_route_unsupported`, never route an OpenAI seat through `opencode`, an API or a gateway. Such routes remain unsupported residuals. An unambiguous Codex host has no Claude marker; its Claude seat retains the existing TUI route.

   Leave `compose_review_board` auth-aware and unchanged: its availability/auth CLI probes are metadata checks, not reviewer launches or native authority. A failed probe can remove OpenAI and backfill another vendor; report that composition shortfall as no Codex seat/no request, not a native deferral or satisfied host seat. Qualification starts with an already-composed eligible seat; host metadata never supplies auth. This plan does not solve native admission when CLI auth/availability is unavailable. Exercise the real composer with independently injected availability and auth outcomes through emit, not only a prebuilt board fixture.
3. **Extend the existing protocol, with explicit request-side posture.** The Codex request names a native Codex subagent, never a Claude affordance or an assumed host-specific tool name. Its emitted text and resolved instructions must state: read only the staged review bundle; no execution, writes, network or tools beyond reading that bundle. This is a tested request statement, not proof the host enforces it. `native_agent_leg_request(leg="codex")` raises `ValueError` with `native_host_required:codex` unless the shared routing decision confirms Codex; ambiguity/conflict keeps its prior refusal. Preserve the Claude builder contract. `native_fill_request_payload`, loader and preflight share Codex eligibility. Accept `--native-leg codex=<dir-or-request.json>` on both commands; retain `claude=` and its `claude.md` fallback only for Claude, while Codex uses `review.md`. Derive continuation text and `filled_by` from the emitted seat. The supplied alias must agree with emitted seat/model; never relabel current digests as emitted-request digests. Artifact, brief, composition, request and seat bindings, stale-train refusal, author exclusion, duplicate refusal, verdict-less degradation and bind-before-president remain load-bearing. Existing CLI preflight precedes minting; invoker fill preflight retains its existing placement after authorization checks and before reviewer dispatch. No new classifier or approval count is introduced.
4. **State the single-request boundary honestly.** This cell qualifies emit for exactly one eligible Codex seat. Refuse multiple eligible Codex seats before request files or reviewer effects. Auth-aware backfill can routinely create this case when another vendor is down. The library may return separate typed deferrals, but no unfilled seat counts and this plan adds no multi-request CLI. Keep Claude's existing `seats[0]` emit behavior unchanged and explicitly residual on agent-harness#924; do not apply the new count check to Claude.
5. **Heartbeat-only remains unsupported for native seats.** Resolve host metadata before whole-board monitoring preflight, using the same injectable environment. A confirmed Codex host seat, existing Claude marker-keyed native seat, explicit `seat.host_leg` or supplied fill under `heartbeat_only` refuses the board before availability/auth, request-directory creation, minting or launch. Extend only the pure preflight's native-host input; preserve its diagnostic family and closed policy vocabulary. Intended changes: Claude-marker heartbeat boards with no fill now refuse rather than run other seats alongside a deferral; Codex-host heartbeat boards refuse rather than launch their own Codex CLI. Retain the Claude-bounded positive control and standalone/default Gemini preflight result with an explicitly empty host environment. With no ambiguity/conflict and no host-vendor seat or other excluded route, existing non-native routes remain eligible. Never select `bounded` automatically, substitute a reviewer, add a model-thinking deadline or invent sandbox facts. This is a protocol cell, **not operational native support under the operator's heartbeat-only requirement**.
