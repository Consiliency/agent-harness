## Mutation Oracle Contract

`mutation_oracle_result.v1` is runner-owned and sealed per parameter from the
pristine baseline checkout and the fresh one-replacement mutation checkout. It
binds the candidate commit, parent criterion and criterion-byte digest,
parameter and mutation IDs, target-path and anchor digest, replacement digest,
exact proof argv and command digest, exact target nodeid, declared and observed
rule IDs, declared and observed normalized failure classes, declared and
observed channels/result codes, `proofgate_mutation_observable` property count
and canonical-value digest, target call-phase reachability, complete
collection/setup/call-phase JUnit identities, stdout/stderr digests, exits, and
bounded runner timing. It records no free-text match as authority. Declared
fields remain expectations only: observed semantic fields come exclusively from
the typed call-phase JUnit property emitted by the intended assertion.

The reducer applies this decision table in order:

| Observation | Mutation status | Aggregate effect |
|---|---|---|
| Pristine exact-command/nodeid baseline is absent, unrun, nonzero, skipped, deselected, or not GREEN | `baseline_failed` | BLOCK; no kill |
| Anchor does not match exactly once or the one replacement is absent/unrun | `mutation_not_applied` | BLOCK; no kill |
| Mutation has syntax/import/collection/setup failure, harness error, timeout, or missing structured evidence | `mutation_harness_block` with exact infrastructure `block_class` | BLOCK; no kill |
| A different nodeid fails, more than the target fails, the target does not reach call phase, or the nonzero is otherwise unrelated | `mutation_harness_block` / `unrelated_failure` | BLOCK; no kill |
| Observed normalized failure class differs from `expected_failure_class` | `mutation_harness_block` / `rejection_class_mismatch` | BLOCK; no kill |
| The exact target nodeid fails but its typed property is missing, duplicated, malformed, or names another assertion/result—including a different failure in that same nodeid—or any criterion digest, rule ID, channel, target nodeid, or result code differs from `expected_observable` | `mutation_harness_block` / `observable_mismatch` | BLOCK; no kill |
| Exact viable target call remains GREEN after the applied mutation | `survived` | Survivor; no kill |
| Baseline is GREEN, mutation is viable, exact target alone reaches call-phase rejection, and every declared oracle field matches exactly | `killed` | Successful kill |

declaration, failure text, stdout, or stderr, and any
aggregate `killed` result containing a baseline failure, non-applied mutation,
