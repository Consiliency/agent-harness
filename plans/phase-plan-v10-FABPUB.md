# FABPUB: Shared Epoch Allocator — Publish Identity

## Context

FABPUB migrates every fresh `publish_committed_branch` admission from caller-stamped `lease_epoch=1` to the broker's single repository-wide monotonic allocator. Repository authority is one canonical Git-common-dir identity, not an absolute linked-worktree path or train-roadmap path; every train using the same broker root and every linked worktree of that repository therefore reaches one allocator/store, while distinct repositories retain distinct stores and ambiguity blast radii. The phase is an independent v10 root and produces `IF-0-FABPUB-1`; FABREADMIT and RESIDUAL remain downstream and must not execute beside this phase because they share publish-identity surfaces.

The roadmap fixes four boundaries. First, `LinearizableAdmissionStore.admit_next` allocates under the existing advisory lock and enforces both values supplied to `make_request(epoch, attempt_id)`. Second, completed-effect identity remains the roadmap-frozen, base-free `publish_committed_branch_idempotency_key(repo, branch, head_sha)`; the `base` question carried by `EC-RESIDUAL-1` is not reopened. Third, approval identity is derived from the transaction's resolved post-commit head and the merge base against its frozen full `base_tip_sha`, never from moving live `HEAD` or a raw base ref after preparation. Fourth, `BrokerService.execute` performs terminal replay first, then requires every fresh or continuing `PUBLISH_COMMITTED_BRANCH` to carry the new epoch-free `PreAdmissionEnvelope` and use `admit_next`; a finalized `AdmissionRequest` remains compatible only for non-publish verbs and already-completed terminal replay. A fresh finalized publish cannot provide transaction identity or commit-stable approval and is rejected before either admission method, broker-intent persistence, or adapter execution.

The live crash hole is also part of this phase. A normal `publish_from_worktree` call currently commits and then enters the broker, but a crash in that gap leaves a clean worktree; the next normal call exits at `nothing_staged` and never reaches `BrokerService.execute`. A checkpoint written only after ref movement leaves the same unrecoverable kill before that write. FABPUB therefore adds a versioned, metadata-only `PublishTransaction` under the train-local coordinator root, persists `PREPARED`, constructs the actual Git commit object without moving the branch, durably persists its exact expected OID/raw-object digest at `COMMIT_OBJECT_DURABLE`, and only then CAS-updates the exact branch ref.

Transaction construction is acyclic and object-first. Stage 1 captures the exact original caller message bytes before any FABPUB trailer, rejects any preexisting `FABPUB-Intent-ID` line, hashes those bytes, and canonicalizes only the immutable pre-trailer intent fields. `transaction_id` is the domain-separated SHA-256 of those canonical pre-trailer bytes; the allowlist contains neither `transaction_id` nor any trailer, final-message, expected/committed-head, or final-commit digest. Stage 2 appends exactly one deterministic `FABPUB-Intent-ID: <transaction_id>` trailer, freezes the exact final message bytes and every commit-construction input—parent OID, tree OID, Git object format, author and committer names/emails/dates/timezones, encoding and ordered extra-header policy, signing mode/key/format and signer input policy, constructor argv/config/environment, and every pre-construction byte that can affect the commit object—and persists `PREPARED`. The normal path then constructs the actual commit object once without changing any ref; when signing is enabled, the resulting exact signature header bytes are captured from that object rather than regenerated on retry. It reads the raw object bytes, obtains `expected_commit_oid` plus `final_commit_object_sha256`, and durably records both, the signature/extra-header bytes, and the complete construction inputs at `COMMIT_OBJECT_DURABLE` before an exact-ref CAS from `parent_head_sha` to `expected_commit_oid`. Recovery never infers or adopts a commit from matching semantic fields: exact ref equality with `expected_commit_oid` may finalize after raw-object digest verification; exact ref equality with `parent_head_sha` may retry the same CAS to the already-recorded object; any other OID blocks. A commit with the same parent/tree/message/trailer but a different author, committer date, signature, encoding, extra header, raw-object digest, or OID is therefore rejected. No identity derivation ever hashes a value that contains the identity being derived. Prebuilt publication never rewrites an existing commit: it applies the same pre-trailer identity construction to its exact caller/presentation inputs, rejects a misleading preexisting FABPUB trailer, and freezes its supplied head as the exact expected/committed OID plus raw-object digest before broker entry.

The allowed durable state progression is `PREPARED -> COMMIT_OBJECT_DURABLE -> COMMITTED_HEAD_RESOLVED -> ADMISSION_DURABLE -> BROKER_INTENT_DURABLE -> ADAPTER_STARTED -> TERMINAL_SEALED`. Every local transition is serialized by the transaction lock and persisted by temp-file write, file fsync, atomic replace, and parent-directory fsync; Git object creation/ref CAS, the admission append, and broker evidence appends remain their authoritative atomic records. Recovery may advance a lagging transaction projection only after exact-OID/raw-object reconciliation proves the corresponding Git object and exact ref, admission record, or broker evidence already exist. The adapter-start marker is durable before the adapter effect: a crash at the preserved broker-intent arm occurs before that marker and may retry, while an `ADAPTER_STARTED` record without terminal evidence is fail-closed as outcome-ambiguous and never re-invokes the adapter. `ABANDONED` and `CONFLICTED` are terminal non-authorizing tombstones. An active mismatch is never overwritten; cleanup can archive a terminal/tombstoned transaction and clear its active pointer only under the same lock and only after the tombstone is durable. A new different-head publish then creates a fresh fully validated intent. Exact terminal records remain replayable so a whole-path retry reaches broker terminal replay instead of `nothing_staged`.

The production allocator route is equally explicit. `CanonicalRepositoryIdentity.v1` is the full domain-separated SHA-256 of the normalized, symlink-resolved absolute Git common-directory identity plus Git object format; linked worktrees share it, distinct local repositories do not, and neither train path nor worktree top-level path is hashed into it. The absolute worktree path remains only a validated adapter execution location and must resolve back to the carried canonical identity. `publish_from_worktree`, `PreAdmissionEnvelope`, broker authority, `publish_attempt_id`, and the unchanged base-free `publish_committed_branch_idempotency_key(repo, branch, head_sha)` use the canonical repository identity as `repo`. `live.py` routes every service/store for that identity to one full-digest directory beneath the shared broker root even when adapters run in different linked worktrees. `cli.py` keeps train-local transaction/coordinator roots but removes the train-path hash from broker allocation scope and passes the same `<ledger-dir>/broker` root to every train invocation.

## Interface Freeze Gates

- [ ] IF-0-FABPUB-1 — `LinearizableAdmissionStore.admit_next(make_request, *, attempt_id, precondition) -> AdmissionRecord` holds `admissions.lock` while it checks `epoch_blocked`, policy, prior records, and the in-lock precondition. On an `attempt_id` hit it rebuilds with `make_request(prior.epoch, attempt_id)`, requires `rebuilt.lease_epoch == prior.epoch` and `rebuilt.attempt_id == attempt_id`, rejects any other authority-field mismatch, and returns the original record. On a miss it allocates `(max(record.epoch) if records else 0) + 1`, calls `make_request(epoch, attempt_id)`, requires `request.lease_epoch == epoch` and `request.attempt_id == attempt_id`, and appends plus fsyncs one record. All production construction routes use one `CanonicalRepositoryIdentity.v1`: normalize and symlink-resolve `git -C <worktree> rev-parse --path-format=absolute --git-common-dir`, pair it with `git rev-parse --show-object-format`, serialize the versioned explicit fields, and derive a full 64-hex domain-separated SHA-256. The worktree path and train path are excluded; distinct Git common directories remain distinct. `publish_from_worktree` carries that identity as repository authority and carries the absolute worktree only as a non-authoritative adapter location that must resolve back to the same identity. `live.py` chooses exactly `<shared_broker_root>/repositories/<canonical_repository_identity>` for both admission and evidence stores regardless of linked worktree or train, never a worktree-path hash or truncated slug. `cli.py` passes train-independent `<ledger-dir>/broker` as `shared_broker_root` while retaining a separately namespaced train-local coordinator/transaction root. Before normal publication, `publish_from_worktree` rejects any caller message containing a `FABPUB-Intent-ID` line and constructs `PublishPreTrailerIntent.v1` from the exact immutable field allowlist: canonical repository identity, branch, base, frozen full `base_tip_sha`, mode, pre-commit parent OID, staged tree OID, ordered owned paths, staged-diff SHA-256, exact original-message byte length and SHA-256, draft/body identity, and envelope-authority pre-image digest. The non-authoritative worktree path is not hashed into repository/transaction/effect identity. The nested authority pre-image is canonicalized from an explicit pre-transaction allowlist and cannot contain `transaction_id` or any final-message/expected-head/committed-head/commit-object field; opaque caller-supplied digests are not accepted. The pre-trailer object is serialized exactly with `json.dumps(payload, sort_keys=True, separators=(",", ":"), ensure_ascii=True).encode("ascii")`, then `pre_trailer_intent_sha256` is recorded and `transaction_id = sha256(b"FABPUB-PUBLISH-TRANSACTION-v1\\0" + pre_trailer_intent_bytes)` is derived. The allowlist excludes `transaction_id`, the trailer, `final_commit_message_sha256`, `expected_commit_oid`, `committed_head_sha`, `final_commit_object_sha256`, and every other field whose bytes could contain or derive from `transaction_id`. Only afterward does it construct exact final message bytes as `original_message_bytes + b"\\n\\nFABPUB-Intent-ID: " + transaction_id.encode("ascii") + b"\\n"` and record `final_commit_message_sha256` separately. Before `PREPARED`, it freezes exact `parent_head_sha`, tree OID, final message bytes, object format, author and committer names/emails/exact dates/timezones, encoding header policy, ordered extra-header allowlist/bytes, signing mode/key/format and signer input policy, constructor argv/config/environment, and every pre-construction byte affecting the object; unsupported or implicit header/signing inputs fail closed. After durable `PREPARED`, it constructs the actual object once without ref mutation, captures exact signature/extra-header bytes from the result, verifies and durably flushes the raw object, obtains exact `expected_commit_oid` and `final_commit_object_sha256`, and persists those values plus the captured bytes atomically at `COMMIT_OBJECT_DURABLE` before any ref change. It then requires `HEAD` to be the exact symbolic `refs/heads/<branch>` and uses `git update-ref refs/heads/<branch> <expected_commit_oid> <parent_head_sha>` (or an equivalently exact transaction) as the sole CAS. Recovery from `COMMIT_OBJECT_DURABLE` reads that exact ref: `ref == expected_commit_oid` may advance after raw-object digest verification; `ref == parent_head_sha` may retry the same CAS to the already-recorded object; every other OID, missing/corrupt expected object, raw-digest mismatch, detached/wrong ref, or alternate same-semantic commit is `CONFLICTED` before admission. It never searches by parent/tree/message/trailer and never adopts, re-signs, or reconstructs another OID. `COMMITTED_HEAD_RESOLVED` records `committed_head_sha == expected_commit_oid`; a same parent/tree/message/single trailer with any different author, committer date, signature, encoding/extra header, raw digest, or OID is rejected. Prebuilt mode does not append, construct, CAS, or rewrite a commit and rejects a preexisting FABPUB trailer; its input head is frozen as exact expected/committed OID plus raw-object digest before broker entry. `BrokerService.execute` computes the base-free completed-effect key with canonical repository identity as the unchanged `repo` input and returns any already-completed terminal-evidence replay before fresh authorization. If replay does not return—including absent evidence or a non-terminal in-flight record—`PUBLISH_COMMITTED_BRANCH` requires an epoch-free `PreAdmissionEnvelope`; a finalized `AdmissionRequest` raises exact `TypeError("fresh publish_committed_branch requires PreAdmissionEnvelope")` before policy classification, either admission method, broker-intent/evidence mutation, or adapter execution. Finalized `AdmissionRequest` retains legacy `admit()` semantics only for non-publish verbs; non-publish envelopes fail before admission. The publish envelope is legal only for `PUBLISH_COMMITTED_BRANCH`, names the exact `COMMITTED_HEAD_RESOLVED` transaction, carries canonical repository identity plus its original-message digest, pre-trailer digest, transaction ID, final-message digest, expected/committed OID, and final-commit-object digest as separately compared bindings, and carries the validated worktree path separately for adapter execution; derives `attempt_id = sha256("publish\\0" + canonical_repository_identity + "\\0" + branch + "\\0" + expected_commit_oid)`; derives approval `base_sha = merge-base(expected_commit_oid, transaction.base_tip_sha)` from full frozen SHAs; rebuilds lease/fence/idempotency fields at the allocated epoch through `admit_next`; and passes only the stored finalized request to the adapter. Thus no fresh publish can bypass the single repository store, broker allocation, acyclic transaction identity, exact expected commit, or commit-stable approval. The transaction reconciles and durably projects `ADMISSION_DURABLE`, `BROKER_INTENT_DURABLE`, `ADAPTER_STARTED`, and `TERMINAL_SEALED` from authoritative admission/evidence records that preserve repository identity, pre-trailer identity, and exact final-commit bindings; only the pre-`ADAPTER_STARTED` broker-intent state may retry adapter execution. Active mismatch, stale/ref-moved state, a trailer-shape conflict, or an abandoned/conflicted tombstone fails closed before admission, and cleanup cannot turn it into publish authority. Terminal replay retains the separate base-free `publish_committed_branch_idempotency_key(repo, branch, head_sha)` with canonical repository identity as `repo`.
