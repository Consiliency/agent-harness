# FABPUB: Shared Epoch Allocator — Publish Identity

## Context

FABPUB migrates every fresh `publish_committed_branch` admission from caller-stamped `lease_epoch=1` to the broker's single repository-wide monotonic allocator. Repository authority is one canonical Git-common-dir identity, not an absolute linked-worktree, train-roadmap, or train-ledger path; every normal CLI train root and linked worktree of that repository therefore derives one allocator/store without a shared-root injection, while distinct repositories retain distinct stores and ambiguity blast radii. The phase begins only after PROOFGATE and CONFORM are recorded completed on canonical main and produces `IF-0-FABPUB-1`; FABREADMIT and RESIDUAL remain downstream and must not execute beside this phase because they share publish-identity surfaces. Before SL-0 it rechecks every owned-path and live-source anchor against that fetched dependency-complete base and repairs/re-panels on drift.

The roadmap fixes four boundaries. First, `LinearizableAdmissionStore.admit_next` allocates under the existing advisory lock and enforces both values supplied to `make_request(epoch, attempt_id)`. Second, completed-effect identity remains the roadmap-frozen, base-free `publish_committed_branch_idempotency_key(repo, branch, head_sha)`; the `base` question carried by `EC-RESIDUAL-1` is not reopened. Third, approval identity is derived from the transaction's resolved post-commit head and the merge base against its frozen full `base_tip_sha`, never from moving live `HEAD` or a raw base ref after preparation. Fourth, `BrokerService.execute` performs terminal replay first, then requires every fresh or continuing `PUBLISH_COMMITTED_BRANCH` to carry the new epoch-free `PreAdmissionEnvelope` and use `admit_next`; a finalized `AdmissionRequest` remains compatible only for non-publish verbs and already-completed terminal replay. A fresh finalized publish cannot provide transaction identity or commit-stable approval and is rejected before either admission method, broker-intent persistence, or adapter execution.

The live crash hole is also part of this phase. A normal `publish_from_worktree` call currently commits and then enters the broker, but a crash in that gap leaves a clean worktree; the next normal call exits at `nothing_staged` and never reaches `BrokerService.execute`. A checkpoint written only after ref movement leaves the same unrecoverable kill before that write. Object-first construction creates a second production-reachability constraint: at `COMMIT_OBJECT_DURABLE` before ref CAS the transaction-owned tree remains staged against the parent, so current `run_train` returns `preflight_failed` at its unconditional clean gate; even if that gate were broadly bypassed, the execute path reruns `run_loop` before it calls `publish_from_worktree`. FABPUB therefore adds a versioned, metadata-only `PublishTransaction` under the train-local coordinator root, persists `PREPARED`, constructs the actual Git commit object without moving the branch, durably persists its exact expected OID/raw-object digest at `COMMIT_OBJECT_DURABLE`, and only then CAS-updates the exact branch ref. The default production `run_train` route must discover and validate that durable transaction before ordinary clean-worktree evaluation, admit only its exact state-specific index/worktree projection, and resume publication before any upstream injection or author work.

Transaction construction is acyclic and object-first. Stage 1 captures the exact original caller message bytes before any FABPUB trailer, rejects any preexisting `FABPUB-Intent-ID` line, hashes those bytes, and canonicalizes only the immutable pre-trailer intent fields. `transaction_id` is the domain-separated SHA-256 of those canonical pre-trailer bytes; the allowlist contains neither `transaction_id` nor any trailer, final-message, expected/committed-head, or final-commit digest. Stage 2 appends exactly one deterministic `FABPUB-Intent-ID: <transaction_id>` trailer, freezes the exact final message bytes and every commit-construction input—parent OID, tree OID, Git object format, author and committer names/emails/dates/timezones, encoding and ordered extra-header policy, signing mode/key/format and signer input policy, constructor argv/config/environment, and every pre-construction byte that can affect the commit object—and persists `PREPARED`. The normal path then constructs the actual commit object once without changing any ref; when signing is enabled, the resulting exact signature header bytes are captured from that object rather than regenerated on retry. It reads the raw object bytes, obtains `expected_commit_oid` plus `final_commit_object_sha256`, and durably records both, the signature/extra-header bytes, and the complete construction inputs at `COMMIT_OBJECT_DURABLE` before an exact-ref CAS from `parent_head_sha` to `expected_commit_oid`. Recovery never infers or adopts a commit from matching semantic fields: exact ref equality with `expected_commit_oid` may finalize after raw-object digest verification; exact ref equality with `parent_head_sha` may retry the same CAS to the already-recorded object; any other OID blocks. A commit with the same parent/tree/message/trailer but a different author, committer date, signature, encoding, extra header, raw-object digest, or OID is therefore rejected. No identity derivation ever hashes a value that contains the identity being derived. Prebuilt publication never rewrites an existing commit: it applies the same pre-trailer identity construction to its exact caller/presentation inputs, rejects a misleading preexisting FABPUB trailer, and freezes its supplied head as the exact expected/committed OID plus raw-object digest before broker entry.

The allowed train-local projection is `PREPARED -> COMMIT_OBJECT_DURABLE -> COMMITTED_HEAD_RESOLVED -> ADMISSION_DURABLE -> BROKER_INTENT_DURABLE -> ADAPTER_STARTED -> TERMINAL_SEALED`, but train-local `ADAPTER_STARTED` is never provider-effect authority. Every local transition is serialized by the transaction lock and persisted by temp-file write, file fsync, atomic replace, and parent-directory fsync; Git object creation/ref CAS, the admission append, and broker evidence appends remain their authoritative atomic records. After completed-terminal replay and full envelope validation but before either admission method or broker-intent mutation, `BrokerService.execute` must acquire and fsync one repository-visible `AdapterStartOwnership.v1` record under the canonical shared evidence-store lock, bound to canonical repository identity, idempotency key, transaction ID, attempt ID, committed head, adapter operation, and a fresh owner nonce. A competing train, attempt, or different-head publish that finds an unsealed shared owner promotes it to permanent `OUTCOME_AMBIGUOUS_BLOCKED` under that same lock and fails closed before admission or adapter entry. The owning train may then admit and persist broker intent; immediately before any provider effect it re-acquires the shared lock and revalidates the exact owner nonce/bindings plus current generation, but does not create a late second owner. A crash after the pre-admission shared marker—whether before admission, before the effect, or after a possible effect—makes recovery append permanent `OUTCOME_AMBIGUOUS_BLOCKED` under the same lock before any new admission/effect; the adapter is never retried. The train-local marker is only a projection of the shared record and remains ordered after `BROKER_INTENT_DURABLE`. Recovery may advance other lagging transaction projections only after exact-OID/raw-object reconciliation proves the corresponding Git object and exact ref, admission record, or broker evidence already exist. `ABANDONED` and `CONFLICTED` are terminal non-authorizing tombstones. An active mismatch is never overwritten; cleanup can archive a terminal/tombstoned transaction and clear its active pointer only under the same lock and only after the tombstone is durable. A new different-head publish then creates a fresh fully validated intent only when no unsealed shared start exists. Exact terminal records remain replayable so a whole-path retry reaches broker terminal replay instead of `nothing_staged`.

The production allocator route is equally explicit. `CanonicalRepositoryIdentity.v1` is the full domain-separated SHA-256 of the normalized, symlink-resolved absolute Git common-directory identity plus Git object format; linked worktrees share it, distinct local repositories do not, and neither train path nor worktree top-level path is hashed into it. The absolute worktree path is carried separately as required `BrokerRequest.adapter_worktree`, remains only a validated adapter execution location, and must resolve back to the canonical identity in `BrokerRequest.repo`. `publish_from_worktree`, `PreAdmissionEnvelope`, broker authority, `publish_attempt_id`, and the unchanged base-free `publish_committed_branch_idempotency_key(repo, branch, head_sha)` use the canonical repository identity as `repo`. Reusing the repository pattern already established by `roadmap_authority.py`, `live.py` resolves the Git common directory from `BrokerRequest.adapter_worktree` before service selection and routes production admission/evidence state to exactly `<resolved-git-common-dir>/phase-loop-fabpub-broker-v1/repositories/<canonical_repository_identity>`. Linked worktrees and train files in unrelated directories therefore converge without caller coordination, realizing the single allocator epoch space selected by `agent-harness#363`. `cli.py` keeps the train-path-derived `<ledger-dir>/broker/<train-key>` only as `CoordinatorRuntime.coordinator_root` for train-local transaction/checkpoint state and calls the production routing builder with no allocator-root argument; `--ledger-dir`, train path/stem/content, CWD, and workspace top-level can neither select nor namespace allocator authority. Explicit broker roots remain injectable only through an unmistakable test-only constructor and are rejected by the activated production CLI/direct route.

That identity switch is not activation-safe by itself. Current production state lives under `<ledger-dir>/broker/<sha256(resolved-train-path)[:16]>/<sha256(serialized-repo-preimage)[:16]>`; the repository preimage is the exact historical string serialized by that caller, which may be relative and is not normalized before hashing, while its resolution context determines the Git repository it denotes. Completed-effect keys hash that same exact historical repository string. FABPUB therefore owns one pre-activation, fail-closed, global repository-partitioned cutover transaction over the complete attested set of legacy train-ledger broker roots, with each partition targeting its canonical Git-common-dir namespace. It inventories every legacy leaf before activation; authenticates each exact serialized repository preimage together with its immutable resolution context and resolved train-path preimage to exactly one canonical Git identity; partitions sources, admission high-water marks, terminal effects, and permanent ambiguity by that identity; then retires all sources and establishes one crash-idempotent logical `ARMED` barrier whose complete, digest-equal partition receipts must exist before any target is routable. Partial writes across roots are recoverable intermediate state, never partial activation. No per-repository receipt may claim that every legacy leaf resolves to itself. A missing, unmapped, multiply mapped, malformed, colliding, conflicting, changed, or partially retired source blocks activation; there is no empty-store fallback, epoch reset, partial repository activation, or adapter retry around legacy evidence.
