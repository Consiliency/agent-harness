# FABPUB: Shared Epoch Allocator — Publish Identity

## Context

FABPUB migrates every fresh `publish_committed_branch` admission from caller-stamped `lease_epoch=1` to the broker's single per-repository monotonic allocator. The phase is an independent v10 root and produces `IF-0-FABPUB-1`; FABREADMIT and RESIDUAL remain downstream and must not execute beside this phase because they share publish-identity surfaces.

The roadmap fixes four boundaries. First, `LinearizableAdmissionStore.admit_next` allocates under the existing advisory lock and enforces both values supplied to `make_request(epoch, attempt_id)`. Second, completed-effect identity remains the roadmap-frozen, base-free `publish_committed_branch_idempotency_key(repo, branch, head_sha)`; the `base` question carried by `EC-RESIDUAL-1` is not reopened. Third, approval identity is derived from the transaction's resolved post-commit head and the merge base against its frozen full `base_tip_sha`, never from moving live `HEAD` or a raw base ref after preparation. Fourth, `BrokerService.execute` performs terminal replay first, then requires every fresh or continuing `PUBLISH_COMMITTED_BRANCH` to carry the new epoch-free `PreAdmissionEnvelope` and use `admit_next`; a finalized `AdmissionRequest` remains compatible only for non-publish verbs and already-completed terminal replay. A fresh finalized publish cannot provide transaction identity or commit-stable approval and is rejected before either admission method, broker-intent persistence, or adapter execution.

The live crash hole is also part of this phase. A normal `publish_from_worktree` call currently commits and then enters the broker, but a crash in that gap leaves a clean worktree; the next normal call exits at `nothing_staged` and never reaches `BrokerService.execute`. A checkpoint written only after commit leaves the same unrecoverable kill before that write. FABPUB therefore adds a versioned, metadata-only `PublishTransaction` under the coordinator-owned root and persists its `PREPARED` intent before `git commit`.

Transaction construction is acyclic and two-stage. Stage 1 captures the exact original caller message bytes before any FABPUB trailer, rejects any preexisting `FABPUB-Intent-ID` line, hashes those bytes, and canonicalizes only the immutable pre-trailer intent fields. `transaction_id` is the domain-separated SHA-256 of those canonical pre-trailer bytes; the allowlist contains neither `transaction_id` nor any trailer, final-message, committed-head, or final-commit digest. Stage 2 appends exactly one deterministic `FABPUB-Intent-ID: <transaction_id>` trailer, hashes the final message separately, and persists `PREPARED`; only then may the normal path invoke `git commit`. After commit, the full Git object ID and a SHA-256 of the raw commit object are recorded separately at `COMMITTED_HEAD_RESOLVED`. Recovery re-derives and compares the original-message digest, canonical pre-trailer bytes/digest, transaction ID, exact final message/digest, parent, and tree; it rejects preexisting, missing, conflicting, malformed, or duplicate trailers, descendants, rewritten heads, and caller mismatches. No identity derivation ever hashes a value that contains the identity being derived. Prebuilt publication never rewrites an existing commit: it applies the same pre-trailer identity construction to its exact caller/presentation inputs, rejects a misleading preexisting FABPUB trailer, and binds the already-committed full head/message/object digests only as separate post-identity fields.

The allowed durable state progression is `PREPARED -> COMMITTED_HEAD_RESOLVED -> ADMISSION_DURABLE -> BROKER_INTENT_DURABLE -> ADAPTER_STARTED -> TERMINAL_SEALED`. Every local transition is serialized by the transaction lock and persisted by temp-file write, file fsync, atomic replace, and parent-directory fsync; Git ref update, the admission append, and broker evidence appends remain their authoritative atomic records. Recovery may advance a lagging transaction projection only after exact-identity reconciliation proves the corresponding Git commit, admission record, or broker evidence already exists. The adapter-start marker is durable before the adapter effect: a crash at the preserved broker-intent arm occurs before that marker and may retry, while an `ADAPTER_STARTED` record without terminal evidence is fail-closed as outcome-ambiguous and never re-invokes the adapter. `ABANDONED` and `CONFLICTED` are terminal non-authorizing tombstones. An active mismatch is never overwritten; cleanup can archive a terminal/tombstoned transaction and clear its active pointer only under the same lock and only after the tombstone is durable. A new different-head publish then creates a fresh fully validated intent. Exact terminal records remain replayable so a whole-path retry reaches broker terminal replay instead of `nothing_staged`.

Canonical runner state is `.phase-loop/`. Legacy `.codex/phase-loop/` compatibility files have no planning authority. The tracked roadmap bytes match the frontmatter digest. The panel record at `.phase-loop/reviews/v10-fabpub-plan-panel.json` binds exact plan digest `19931d60b0d3a291717d3e1288e09069229e21df375f2b8decb56bc4f3e9c015`: Grok and Gemini returned `AGREE`, Sol returned `DISAGREE` on circular transaction identity, and Fable was intentionally deferred. This revision supersedes exactly that circular construction while preserving the already-fixed fresh-finalized-publish rejection and every other TDD lifecycle, crash/idempotency, publication-identity, provenance, and lane-isolation contract. The revised digest must clear the roadmap-required four-seat plan panel before SL-0.

## Interface Freeze Gates

- [ ] IF-0-FABPUB-1 — `LinearizableAdmissionStore.admit_next(make_request, *, attempt_id, precondition) -> AdmissionRecord` holds `admissions.lock` while it checks `epoch_blocked`, policy, prior records, and the in-lock precondition. On an `attempt_id` hit it rebuilds with `make_request(prior.epoch, attempt_id)`, requires `rebuilt.lease_epoch == prior.epoch` and `rebuilt.attempt_id == attempt_id`, rejects any other authority-field mismatch, and returns the original record. On a miss it allocates `(max(record.epoch) if records else 0) + 1`, calls `make_request(epoch, attempt_id)`, requires `request.lease_epoch == epoch` and `request.attempt_id == attempt_id`, and appends plus fsyncs one record. Before a normal commit, `publish_from_worktree` rejects any caller message containing a `FABPUB-Intent-ID` line and constructs `PublishPreTrailerIntent.v1` from the exact immutable field allowlist: canonical repo/worktree identity, branch, base, frozen full `base_tip_sha`, mode, pre-commit parent SHA, staged tree SHA, ordered owned paths, staged-diff SHA-256, exact original-message byte length and SHA-256, draft/body identity, and envelope-authority pre-image digest. That nested authority pre-image is itself canonicalized from an explicit pre-transaction allowlist and cannot contain `transaction_id` or any final-message/head/commit field; opaque caller-supplied digests are not accepted. The pre-trailer object is serialized exactly with `json.dumps(payload, sort_keys=True, separators=(",", ":"), ensure_ascii=True).encode("ascii")`, then `pre_trailer_intent_sha256` is recorded and `transaction_id = sha256(b"FABPUB-PUBLISH-TRANSACTION-v1\\0" + pre_trailer_intent_bytes)` is derived. The allowlist excludes `transaction_id`, the trailer, `final_commit_message_sha256`, `committed_head_sha`, `final_commit_object_sha256`, and every other field whose bytes could contain or derive from `transaction_id`. Only afterward does it construct exact final message bytes as `original_message_bytes + b"\\n\\nFABPUB-Intent-ID: " + transaction_id.encode("ascii") + b"\\n"`, record `final_commit_message_sha256` separately, persist `PREPARED`, and invoke `git commit --cleanup=verbatim -F -`. A restart resolves `COMMITTED_HEAD_RESOLVED` only when retry inputs reconstruct the same original-message and pre-trailer digests/identity and current `HEAD` has the intent's exact parent/tree plus exactly one matching terminal trailer; it then records the full `committed_head_sha` and `final_commit_object_sha256` separately and never feeds either back into `transaction_id`. It never re-commits that head and never uses a moving ref. Prebuilt mode does not append or rewrite a commit and rejects a preexisting FABPUB trailer; its existing head/message/object digests are separate final bindings, never transaction-ID inputs. `BrokerService.execute` computes the base-free publish completed-effect key and returns any already-completed terminal-evidence replay before fresh authorization. If replay does not return—including absent evidence or a non-terminal in-flight record—`PUBLISH_COMMITTED_BRANCH` requires an epoch-free `PreAdmissionEnvelope`; a finalized `AdmissionRequest` raises exact `TypeError("fresh publish_committed_branch requires PreAdmissionEnvelope")` before policy classification, either admission method, broker-intent/evidence mutation, or adapter execution. Finalized `AdmissionRequest` retains legacy `admit()` semantics only for non-publish verbs; non-publish envelopes fail before admission. The publish envelope is legal only for `PUBLISH_COMMITTED_BRANCH`, names the exact `COMMITTED_HEAD_RESOLVED` transaction and carries its original-message digest, pre-trailer digest, transaction ID, final-message digest, committed head, and final-commit-object digest as separately compared bindings; derives `attempt_id = sha256("publish\\0" + repo + "\\0" + branch + "\\0" + transaction.committed_head_sha)`; derives approval `base_sha = merge-base(transaction.committed_head_sha, transaction.base_tip_sha)` from full frozen SHAs; rebuilds the lease/fence/idempotency fields at the allocated epoch through `admit_next`; and passes only the stored finalized request to the adapter. Thus no fresh publish can bypass broker allocation, acyclic transaction identity, or commit-stable approval. The transaction reconciles and durably projects `ADMISSION_DURABLE`, `BROKER_INTENT_DURABLE`, `ADAPTER_STARTED`, and `TERMINAL_SEALED` from authoritative admission/evidence records that preserve the separate pre-trailer and final-commit bindings; only the pre-`ADAPTER_STARTED` broker-intent state may retry adapter execution. Active mismatch, stale/ref-moved state, a trailer-shape conflict, or an abandoned/conflicted tombstone fails closed before admission, and cleanup cannot turn it into publish authority. Terminal replay retains the separate base-free `publish_committed_branch_idempotency_key(repo, branch, head_sha)`.
