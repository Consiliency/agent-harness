# Supervised worker readiness

CLOSEOUT implements the public v2 intake, passive binding bootstrap, captured
admission and bounded worker/journal/reader integration. EC-CLOSEOUT acceptance
remains blocked on independently produced evidence. The pinned publisher is
provisional and `byte_pin_authority` remains false. The receipt is an assessment,
never a runtime authorization input.

| Surface | Evidence and scope | Readiness |
| --- | --- | --- |
| Offline source | Named V0–V3 groups, real temporary operator records, fake local providers, path-entered controls and exact published vectors | Reported per runner outcome in the CLOSEOUT receipt; no live provider calls |
| On-main | Protected-main checks, content applicability and authenticated publication/evidence artifacts | Requires hosted evidence for the assessed content after landing |
| Installed wheel | Packaged exact resource bytes and isolated wheel imports; the coordinator owns final Gate A | Independent installed checks required; source results do not substitute |
| External controller | All 13 apply outcomes from the controller maintainer | Blocked: producer trust root and artifacts unresolved |
| External display | Byte-exact reader reconciliation from the display maintainer | Blocked: producer trust root and artifacts unresolved |
| Independent reviews | Board and separate-president metadata bound to reviewed content | Blocked until approved publisher identities and artifacts exist |
| Installed provider and live use | Independently collected current qualification and operator deployment | Unqualified by this offline implementation; no live run performed |

The contract publisher owns the reviewed non-provisional successor input. The
controller and display maintainers own their evidence. The review evidence
publisher owns the board and separate-president bindings. These unresolved
edges are `upstream_phase_unmet`, with `human_required=false`; no immediate
operator approval is requested by the reducer.

Run `bash phase-loop-runtime/scripts/verify_supervised_v2.sh V0` through `V3`
(or `all`) in the locked source environment. The wrapper records production
symbol witnesses without argument values. The external test-host admission,
PSI and serial execution rules still apply. Producers run before
`stamp_evidence_receipt.py`; the receipt consumer runs after stamping. Historical
receipts and `uv.lock` remain unchanged. CLOSEOUT's receipt pins only its own
sources, tests and frozen inputs, never shared inventories, docs or workflows.

The hosted `supervised-v2-evidence` workflow authenticates evidence through the
GitHub API and publishes a metadata-only assessment even when prerequisites are
missing. A later read-only assessment resolves and hashes that artifact. It
requires live protected-main checks, full-path contract publication, Gate A and
review/external evidence. Successful offline V3 controls cannot certify an
external producer. Absent or skipped-only outcomes never count as proof.

Content identity hashes sorted Git tree rows using RFC 8785 and excludes exactly
`plans/evidence/supervised-worker/CLOSEOUT.md`. A proposed stamp must descend
from the tested head and change only that path. A squash landing additionally
needs API-confirmed PR/merge correspondence and identical governing content.
Later governing changes invalidate applicability and require fresh evidence.

Production reads the fixed passwd-home operator binding; provisioning it is
outside CLOSEOUT. Required dependencies, interactive routes, workspace-contained
executables and unsupported provider routes keep their existing refusals. The
implementation adds no provider probe, registry activation, release or merge
authority. See [contracts](supervised-worker-contracts.md),
[worker behavior](supervised-worker.md) and [status](supervised-run-status.md).

Obligation assessment separates case-specific `offline_production_covered` rows
from `family_witnessed` rows. The latter record related production activity and
supply no obligation-level acceptance claim. The assessment reports counts for
each category; EC-CLOSEOUT-1 cannot be closed by family fallback.

The evidence assessment check must not itself be branch-required: that creates
a self-dependency while it is running. The verifier returns the deterministic
`assessment_check_self_dependency` refusal for that configuration. All other
required checks, including source verification, must authenticate as completed
and successful; sharing a workflow run ID grants no exception.
