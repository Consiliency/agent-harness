### CI: required checks run in the merge queue; changelog entries are fragments (agent-harness#1702)

- The six required checks (`suite gate`, `lint (pyflakes)`, `chronology retention guard`,
  `docs-freshness audit`, `gitleaks`, `check`) also run on `merge_group`, so a GitHub merge
  queue can test each pull request merged onto `main` before it lands. `test.yml` treats a
  queue run like a push to `main`: all three Python lanes, the quarantined tests, the
  CONFORM chronology node and Gate A. Queue runs never take the `ai` offload.
- Pull requests add `changelog.d/<number>.<type>.md` instead of editing `[Unreleased]`
  (see `changelog.d/README.md`); `scripts/assemble_changelog.py` folds them into this file
  at the release cut. `phase-loop docs-audit` accepts a `changelog.d/<number>…md` fragment
  wherever it asks for a CHANGELOG entry.
