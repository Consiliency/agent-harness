Shared placement contract (agent-harness#1792)

The source is `phase_loop_runtime/baml_src/placement_contract.baml`.
From the repository root, regenerate with:

```sh
phase-loop-runtime/.venv/bin/python phase-loop-runtime/scripts/emit_placement_contract.py
```

agent-toolkit vendors `placement_contract.gen.ts`. It needs no BAML runtime,
TypeScript compiler or bundler; Node's native type stripping can load it.
The header records the source digest and pinned baml-cli version. The vendoring
commit identifies the agent-harness revision without self-referential SHA churn.

Coordinator v1 follows agent-harness#1795 revisions 6–9: revision 6 is the wire
schema, revision 7 adds `unavailable`, revision 8 makes exposures HTTP only, and
revision 9 adds the reserve and renew bodies and reclaim records.
Select a schema with `$ref: '#/$defs/CreateBody'` (or the other wire type) and
include `$defs`. Requests reject unknown properties; responses allow them. Use a
format checker for UUID and timestamp validation. In responses and non-request
placement types, optional fields may be absent or null, and the explicitly
nullable revision 6 response keys remain required. **Request optionals**
(`InventoryQuery.page_size`, `page_token`) may be omitted but never sent as `null`.
`DeadlineHeaders` describes X-Deadline-Ms, and `InventoryQuery` describes query
parameters; these are not JSON request bodies.

The only extension to the primitive/reference parser subset is
`map<string, baml.json.json>`, permitted only at `CreateBody.policy`.
BAML 0.23.0 exposes this builtin JSON value type. Policy is an opaque JSON
object, passed through and hashed with RFC 8785 JCS + SHA-256. The emitter
models no OpenShell policy internals; TS uses recursive JsonValue, and the
schema requires only an object. Other maps and unions are refused.

Golden vectors are reference data, not regenerated by the emitter. Digest
vectors carry the exact JCS UTF-8 text and lowercase SHA-256 (without prefix).
Validation vectors state the schema keyword that must reject each invalid case.

Schema validation cannot enforce certificate identity, workload-dependent empty
exposures (CreateBody has no workload), digest equality against reserve/the actual
policy, image allowlists, monotonic flags, immutable binding, label lookup,
destruction evidence, relative-deadline enforcement or snapshot continuity.
Those remain coordinator/client obligations. Terminal display states alone
never prove release: flags are authoritative, including barrier_confirmed.

Python's passive mappings retain timeout uncertainty. `unknown_lease` maps to
no answer; recovery must kill to create a tombstone and confirm. Codes absent
from the older mapping table map as follows:
- `digest_mismatch` (create only) and `invalid_request` (any phase) map to no
  ladder code. On reserve, `invalid_request` means nothing is held. **At create,
  the reserved lease still holds capacity, so the client kills it (tombstone,
  then confirm) before moving on.** The caller decides from the phase.
- `duplicate_binding` maps to release_unconfirmed until kill confirms every
  label match is destroyed.
- `lifetime_exceeded` (renew only) and `snapshot_expired` (inventory only) map to
  no ladder code. The run ends before the lease's current expiry, and a listing
  restarts from page 1. Only a listing that still can't complete leaves release
  unconfirmed.

- `unavailable` (revision 7) maps to `sandbox_placement_unreachable`: it is sent
  only when nothing was reserved or dispatched, so nothing is held.

These are context-sensitive recovery signals, not automatic ladder actions.
Nothing here enables the placement driver. The adoption bundle excludes
`placement_contract.baml`, because it isn't a dotfiles adoption schema.

The pinned official TS generator preserves BAML identifiers in enum values and
class property names even with @alias. Parity checks compare these declared
names/values, then verify our wire aliases through official `baml-cli describe` output.
Our generated wire TS deliberately uses alias values and names.

**Service exposure (agent-harness#1795 revision 8):** `service_exposures` is HTTP
only (`protocol` = `"http"`). Stock OpenShell exposes HTTP services and has no raw
TCP exposure. A raw TCP link, such as agent-toolkit's runner link, uses
`ForwardTcp` (`openshell forward service`) with no exposure entry. Both clients
currently send `service_exposures: []`.

**Request optionals** (for example `InventoryQuery.page_size`) may be omitted but
never sent as `null`. `LeaseStatus.expires_at` must be RFC 3339 UTC (`Z` or
`+00:00`), checked by pattern, because JSON Schema `format` isn't asserted by default.

**Digest spelling:** `vectors/policy-digests.json` stores the SHA-256 as bare
lowercase hex (`sha256`). On the wire, `policy_digest` is `"sha256:" + hex`.

**Timestamps:** `expires_at` is RFC 3339 UTC with seconds 00–59. Leap seconds
(`:60`) are refused so that every validator agrees (agent-harness#1797).

**Revision 9:** `ReserveBody` (`workload`, `ttl_s` 1–3600, `image_digest`,
`policy_digest`) and `RenewBody` (`extend_s` 1–3600) are request types, with
**no `client` or `owner` field**: both come from the certificate. Reserve and
renew answer with a `LeaseStatus`. `LeaseStatus.reclaims` may be absent but is
never `null`. Each `ReclaimRecord` carries a closed `reason` (`unbound`,
`duplicate_binding`, `lease_expired`, `lease_fenced`, `recovery_orphan`) and an
`outcome` (`destroyed`, `destroy_pending`).

**Pattern anchoring:** every pattern ends `$(?![\s\S])`. Python's `re` lets `$`
match before a final newline and ECMAScript's doesn't. The lookahead makes
both refuse a trailing `"\n"`. Ports to other regex engines must keep that
end-of-input meaning.

**State and flags:** `flags` are authoritative and `state` is a derived summary,
so a `state` must never contradict its flags. These are necessary conditions,
checked over every valid vector:
- every state except `tombstone` has `reserved`;
- `tombstone` is `fenced` and `barrier_confirmed`, never `reserved`. It may carry a
  `sandbox_id` when a sandbox found later (an out-of-band create, or an
  unknown-lease label) was bound and destroyed under it;
- `reserved` and `creating` are neither `fenced` nor `ready`;
- `ready` is `create_settled` and `ready`, has a `sandbox_id`, and isn't `fenced`;
- `killing` is `fenced` without `barrier_confirmed`;
- `destroyed` is `fenced` and `barrier_confirmed`;
- `expired` has `expired`.
